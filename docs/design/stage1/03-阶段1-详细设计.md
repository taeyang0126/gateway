## 3. 配置模型
### 3.1 服务配置
```yaml
gateway:
  port: 8080
  max-content-length: 5242880
  pooled-allocator-enabled: true
  health-endpoint-enabled: true
  metrics-endpoint-enabled: true
  management-allowed-client-ips:
    - 127.0.0.1
    - ::1
  max-pending-per-route: 1024
```

- `max-content-length` 默认值为 `5242880`（5MB），用于请求/响应自适应聚合阈值。

### 3.2 路由配置
```yaml
routes:
  - routeId: r-exact-ping
    priority: 100
    matchType: EXACT
    path: /api/ping
    hostRewriteMode: PRESERVE
    upstream:
      scheme: http
      host: 127.0.0.1
      port: 9001
      connectTimeoutMs: 1000
      readTimeoutMs: 1000
      writeTimeoutMs: 1000

  - routeId: r-prefix-api
    priority: 10
    matchType: PREFIX
    path: /api/
    hostRewriteMode: REWRITE
    upstream:
      scheme: http
      host: 127.0.0.1
      port: 9002
      connectTimeoutMs: 1000
      readTimeoutMs: 1000
      writeTimeoutMs: 1000
```

### 3.3 字段约束
- `routeId`：全局唯一。
- `priority`：整型，越大越优先。
- `matchType`：`EXACT` 或 `PREFIX`。
- `path`：必须以 `/` 开头。
- `hostRewriteMode`：`REWRITE` 或 `PRESERVE`，默认 `PRESERVE`。

## 4. 路由匹配算法
```text
输入：requestPath, routeList
1. candidates = 所有命中 requestPath 的路由
2. 按 priority 降序排序
3. 若仍有并列，EXACT 优先于 PREFIX
4. 若均为 PREFIX，按 path 长度降序（最长前缀优先）
5. 若仍并列，按配置声明顺序取第一条
6. 无命中时走默认兜底路由（若存在）
```

## 5. 请求处理时序
```text
Client Request
  -> DefaultHttpServerHandler
      -> 解析 TraceId 与 clientIp
      -> 命中管理端点时执行访问控制（IP 白名单）
      -> RouteService(路由决策)
      -> HeaderPolicyService
          -> 删除 Hop-by-Hop
          -> 写 X-Forwarded-For/Proto/Host
          -> Host 按 hostRewriteMode 处理
      -> 请求体策略判定
          -> chunked / 未知长度 / 超阈值：流式转发
          -> 已知长度且 <= 阈值：聚合转发
      -> UpstreamRouteClient(按路由连接复用 + backlog 有界保护)
      -> ReusableUpstreamResponseHandler
          -> 响应体策略判定（同请求侧规则）
      -> GatewayMetricsService
      -> DefaultHttpServerHandler(SLF4J 访问日志)
  -> Client Response
```

## 6. Header 处理细节
### 6.1 删除的 Hop-by-Hop 头
- `Connection`
- `Keep-Alive`
- `TE`
- `Trailer`
- `Upgrade`
- `Proxy-Authenticate`
- `Proxy-Authorization`
- `Transfer-Encoding`

### 6.2 Forwarded 语义
- 必写：
  - `X-Forwarded-For`：追加客户端 IP。
  - `X-Forwarded-Proto`：写 `http`。
  - `X-Forwarded-Host`：写客户端原始 `Host`。
- 可选：
  - `Forwarded`：`for=<ip>;proto=http;host=<original-host>`。

### 6.3 Host 策略
- `REWRITE`：转发时将 `Host` 改为上游 `host[:port]`。
- `PRESERVE`：保留客户端原始 `Host`。
- 默认值：`PRESERVE`（可按路由切换为 `REWRITE`）。

### 6.4 请求/响应体转发策略
- 统一规则（请求与响应都使用）：
  1. `Transfer-Encoding: chunked` -> 流式。
  2. `Content-Length` 已知且 `<= maxContentLength` -> 聚合。
  3. `Content-Length` 未知或 `> maxContentLength` -> 流式。
- 说明：
  - 是否“流式”是网关内部处理路径，不等同于对外必须回写 `Transfer-Encoding: chunked`。
  - 聚合路径会在内存中组装完整字节数组后再一次性回写。

## 7. 超时与错误映射
### 7.1 超时控制
- `connectTimeoutMs`：建连超时。
- `readTimeoutMs`：上游读超时。
- `writeTimeoutMs`：写上游超时。

### 7.2 错误码映射
| 场景 | category | status | code |
|---|---|---|---|
| 上游连接拒绝/不可达 | UPSTREAM_ERROR | 502 | UPSTREAM_UNAVAILABLE |
| 上游响应超时 | UPSTREAM_ERROR | 504 | UPSTREAM_TIMEOUT |
| 网关内部异常 | GATEWAY_ERROR | 500 | GATEWAY_INTERNAL_ERROR |
| 非法请求 | GATEWAY_ERROR | 400 | BAD_REQUEST |

### 7.3 错误响应体
```json
{
  "timestamp": "2026-03-14T20:00:00+08:00",
  "traceId": "a1b2c3d4e5f6",
  "category": "UPSTREAM_ERROR",
  "code": "UPSTREAM_TIMEOUT",
  "message": "upstream read timeout",
  "status": 504
}
```

## 8. 可观测性设计
- 访问日志字段：`traceId`、`uri`、`method`、`status`、`latencyMs`、`routeId`、`upstream`、`errorCode`。
- 访问日志实现：`DefaultHttpServerHandler` 直接通过 SLF4J 输出，不额外抽象 `AccessLogService`。
- 健康检查：`/health` 仅检查网关进程与事件循环可用性，返回 `200 OK`。
- 指标端点：`/metrics/prometheus`，由 `GatewayMetricsService` 聚合并导出。
- 管理端点访问控制：`/health`、`/metrics/prometheus` 仅允许 `managementAllowedClientIps` 中的来源访问。

## 9. 测试设计
### 9.1 单元测试
- `RouteServiceTests`：精确匹配、前缀匹配、最长前缀、priority 冲突。
- `HeaderPolicyServiceTests`：Hop-by-Hop 移除、X-Forwarded-* 写入、Host `REWRITE/PRESERVE`。
- `TimeoutPolicyTests`：连接/读/写超时触发与错误码映射。
- `ServerPipelineFactoryTests`：服务端 Pipeline 仅保留 `HttpServerCodec + HttpServerKeepAliveHandler + DefaultHttpServerHandler`。

### 9.2 集成测试
- `HttpProxyIT`：`GET /api/ping` 成功代理并回 200。
- `HttpProxyIT`：`Content-Length` 超阈值时，请求与响应都走流式。
- `HttpProxyIT`：6MB 真大文件请求/响应在默认 5MB 阈值下走流式。
- `HttpProxyIT`：显式 `Transfer-Encoding: chunked` + 真文件上传走流式并正确透传到上游。
- `HttpProxyFailureIT`：上游不可达返回 502；上游超时返回 504。
- `HealthEndpointIT`：`/health` 快速返回 200。
- `PrometheusEndpointIT`：`/metrics/prometheus` 导出关键指标，并校验管理端点白名单拦截 403。
- `AccessLogIT`：校验访问日志字段完整性（traceId/URI/status/latency/routeId/upstream）。
- `BacklogProtectionIT`：校验单路由 backlog 溢出时返回 503（`UPSTREAM_BACKLOG_OVERFLOW`）。

### 9.3 性能与稳定性验证
- 工具：Gatling。
- 目标：`>=2000 RPS`、`p99 <= 20ms`。
- 10 分钟窗口采集：RSS 增幅、FD 波动、GC STW p99。
