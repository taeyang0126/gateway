# 阶段 5 需求：安全能力与管理面

## 1. 阶段目标
- 完成网关基础安全防护能力，满足生产接入基本要求。
- 提供轻量管理面 API，支持在线查看与调整关键配置。

## 2. 范围
### 2.1 In Scope
- 认证：API Key、JWT
- 鉴权：按路由的访问控制
- 传输安全：TLS 终止、上游 TLS 校验、mTLS（生产环境强制）
- 基础安全策略：IP 黑白名单、请求体大小限制
- 管理面：只读状态查询 + 单实例受控配置更新接口

### 2.2 Out of Scope
- 完整 OAuth2 授权服务
- 高级 WAF 规则引擎
- 多租户组织权限体系

## 3. 功能需求
- `FR-5-1` 支持路由级 API Key 校验，失败返回 401。
- `FR-5-2` 支持 JWT 签名校验和过期校验，失败返回 401。
- `FR-5-3` 支持按路由配置角色/权限规则，不满足返回 403。
- `FR-5-4` 支持 IP 黑白名单策略，策略命中可拒绝请求。
- `FR-5-5` 支持请求体大小限制，超限返回 413。
- `FR-5-6` 提供管理面接口：路由列表、上游状态、限流状态、熔断状态。
- `FR-5-7` 管理面更新操作必须具备鉴权与审计日志。
- `FR-5-8` 支持网关入口 TLS 终止，支持配置最小 TLS 版本和加密套件。
- `FR-5-9` 支持上游 HTTPS 证书校验（证书链、主机名校验）。
- `FR-5-10` 管理面调用必须支持 mTLS（双向证书认证），生产环境必须强制开启；控制面调用安全由阶段 6A 验收闭环。
- `FR-5-11` 支持证书热更新、到期告警与轮换流程。
- `FR-5-12` 支持密钥版本化与轮换窗口，JWT 支持吊销或黑名单机制。
- `FR-5-13` 管理面必须支持操作级 RBAC（只读、运维、管理员）。
- `FR-5-14` 阶段 5 管理面变更必须通过“配置唯一真源（Single Source of Truth）”写入，不允许绕过版本控制直接生效。
- `FR-5-15` 证书校验必须支持吊销检查（CRL 或 OCSP），校验失败默认拒绝（Fail-Closed）。
- `FR-5-16` 私钥必须存储在受控密钥系统（KMS/HSM 或等效机制）并采用最小权限访问。
- `FR-5-17` JWT 吊销状态跨实例同步能力在阶段 5 仅定义接口与数据模型，不落地分发实现；阶段 6A 负责实现与传播时延验收。
- `FR-5-18` 阶段 5 仅支持单实例配置变更，不包含多实例发布编排与批量分发。
- `FR-5-19` 敏感机密（私钥、API Key、JWT 签名密钥、控制面签名密钥）必须统一纳入机密管理：
  - 统一 KMS/HSM 或等效机制托管。
  - 支持机密轮换、读取审计、最小权限控制。
  - 禁止在配置文件中明文持久化。

## 4. 非功能需求
- `NFR-5-1` 安全校验失败必须快速返回，不访问上游。
- `NFR-5-2` 认证鉴权链路附加延迟均值不超过 3ms。
- `NFR-5-3` 管理面接口默认只监听内网地址，禁止公网裸露。
- `NFR-5-4` TLS 开启后，网关附加延迟增幅不高于 10%（以阶段 4 基线为对比）。
- `NFR-5-5` 审计日志默认保留不少于 180 天，敏感字段必须脱敏。
- `NFR-5-6` 生产环境管理面必须启用 mTLS 和证书主体白名单（CN/SAN Allowlist）。
- `NFR-5-7` 单实例内 JWT 吊销状态生效延迟不高于 1 秒。
- `NFR-5-8` 私钥明文文件不得落地到应用工作目录。
- `NFR-5-9` 阶段 5 不允许出现多实例控制面批量编排入口，仅允许单实例受控变更。
- `NFR-5-10` 审计日志必须支持防篡改与完整性校验（签名链或等效机制）。

## 5. 验收标准
- `AC-5-1` 未携带或携带错误 API Key 请求返回 401。
- `AC-5-2` JWT 过期或签名错误请求返回 401。
- `AC-5-3` 无权限角色访问受限路由返回 403。
- `AC-5-4` 请求体超过阈值时直接返回 413，且不上游。
- `AC-5-5` 管理面可查询关键运行状态，最小字段集必须包含：路由总数、健康实例数、限流命中数、熔断状态、证书有效期。
- `AC-5-6` HTTPS 入口握手成功，TLS 版本和套件不满足策略时握手失败。
- `AC-5-7` 证书轮换可在不停机条件下完成，新证书生效且旧证书按策略下线。
- `AC-5-8` 管理面更新操作必须落审计，且可追溯到操作者、时间、变更内容、版本号。
- `AC-5-9` 管理面配置更新必须通过配置版本控制链路生效，禁止绕过“配置唯一真源（Single Source of Truth）”直接改内存配置。
- `AC-5-10` 生产环境管理面访问在未提供合法 mTLS 客户端证书时必须被拒绝。
- `AC-5-11` 证书吊销后，基于该证书的连接必须在校验阶段被拒绝。
- `AC-5-12` 私钥读取必须通过受控密钥系统授权，未授权访问必须失败并记录审计。
- `AC-5-13` 阶段 5 的配置更新仅影响本实例，不触发跨实例分发行为。
- `AC-5-14` 在阶段 4 基线场景下开启 TLS 后，网关附加延迟增幅不高于 10%。
- `AC-5-15` 单实例内 JWT 吊销状态在 1 秒内生效，超过阈值触发告警。
- `AC-5-16` 运行前安全扫描必须通过：应用工作目录不存在明文私钥与明文机密文件。
- `AC-5-17` 机密轮换后，新版本密钥在不停机条件下生效，旧密钥按策略失效并有审计记录。
- `AC-5-18` 审计日志完整性校验失败时必须触发高优先级安全告警。

## 6. 测试要求
- 单元测试：
  - JWT 校验
  - 权限判定
  - IP 策略判定
  - 请求体限制
- 集成测试：
  - 认证失败与鉴权失败链路
  - 管理面鉴权与审计

## 7. 设计输入清单
- 认证鉴权 Filter 链顺序
- 安全策略配置模型
- 管理面 API 规范与权限模型
- 审计日志字段规范

## 8. 风险与约束
- `RISK-5-1` 若时钟不同步，JWT 过期判断可能出现误差。
- `RISK-5-2` 管理面鉴权薄弱会形成高风险入口。
