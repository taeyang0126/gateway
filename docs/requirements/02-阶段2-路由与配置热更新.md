# 阶段 2 需求：路由与配置热更新

## 0. 版本状态
- 状态：`FROZEN`
- 冻结日期：2026-03-15
- 冻结说明：阶段2需求已完成本轮文档评审与冻结，后续改动需走需求变更流程并记录到 `CHANGELOG-REQUIREMENTS.md`。

## 1. 阶段目标
- 在阶段 1 基础上实现可配置路由能力，支持网关规则迭代。
- 建立配置热更新机制，避免每次改规则都重启网关。

## 2. 范围
### 2.1 In Scope
- 多条件路由：Host、Path、Method
- 路径重写与前缀剥离
- 上游服务多节点与基础负载均衡
- 配置文件热更新（本地文件）
- 上游健康检查（主动探测、被动摘除、自动恢复）
- 最小健康实例保护与降级策略
- 配置唯一真源与运行时写入防护
- 路由模型扩展位预留（仅数据模型/接口占位，不实现 L4 运行逻辑）

### 2.2 Out of Scope
- 注册中心动态发现（本阶段不落地实现，仅保留抽象扩展点）
- 灰度发布和流量染色
- UI 管理后台
- 长连接会话变更策略（归阶段 3/6B）
- 熔断/重试治理策略（归阶段 4）

## 3. 功能需求
- `FR-2-1` 支持路由匹配条件：Host、Path 前缀、HTTP Method。
- `FR-2-2` 支持路径改写：前缀替换、剥离前缀。
- `FR-2-3` 单路由支持配置多个上游节点。
- `FR-2-4` 必须支持负载均衡策略：轮询（Round Robin）。
- `FR-2-5` 网关必须支持配置文件监听与热更新，更新后新请求生效。
- `FR-2-6` 热更新失败时必须回滚到上一版本配置并告警日志。
- `FR-2-7` 提供配置校验能力，非法配置不得生效。
- `FR-2-8` 必须支持上游健康检查：
  - 主动健康检查（周期探测 + 连续失败阈值摘除 + 连续成功阈值恢复）。
  - 被动健康检查（5 秒滑动窗口失败率与失败次数联合触发临时摘除）。
- `FR-2-9` 必须支持最小健康实例保护，避免全部节点被同时摘除导致路由雪崩：
  - 支持 `minHealthyInstances`（默认值 1）。
  - 当摘除后健康实例数小于 `minHealthyInstances` 时，进入降级态并告警，不得继续执行摘除动作。
- `FR-2-10` 必须定义配置唯一真源（Single Source of Truth）：
  - 阶段 2 以本地配置文件为配置唯一真源。
  - 运行时不允许第二写入源直接修改生效配置。
- `FR-2-11` 必须预留协议路由扩展模型，支持后续阶段增加 L4 路由维度（端口、SNI、目标组）：
  - 仅实现数据模型和接口扩展位占位。
  - 本阶段不得实现 L4 运行时路由逻辑。
- `FR-2-12` 必须定义可预测的路由优先级规则：
  - 先按 `priority` 值降序匹配。
  - 同优先级按匹配特异性排序（Host + Path + Method > Host + Path > Path）。
  - 仍冲突时按配置声明顺序优先。

## 4. 非功能需求
- `NFR-2-1` 路由匹配开销在 1,000 条路由规模下可控，匹配耗时均值 < 1ms。
- `NFR-2-2` 热更新过程不中断现有 HTTP 请求生命周期，不影响正在处理中的 HTTP 请求。
- `NFR-2-3` 配置更新到生效延迟不高于 3 秒。
- `NFR-2-4` 单节点故障被动摘除延迟不高于 5 秒（按 `FR-2-8` 的 5 秒滑动窗口规则判定），主动恢复探测周期可配置。
- `NFR-2-5` 默认健康检查阈值：
  - 主动探测周期默认 2 秒。
  - 连续失败阈值默认 3 次。
  - 连续成功恢复阈值默认 2 次。
  - 被动摘除窗口默认 5 秒，失败率阈值默认 80%，且窗口内失败次数不少于 5 次。
  - `minHealthyInstances` 默认值 1。

## 5. 验收标准
- `AC-2-1` 同时存在 3 条路由规则时，请求按预期命中对应路由。
- `AC-2-2` 配置文件新增路由后，无需重启即可处理新路由流量。
- `AC-2-3` 配置文件语法错误时，网关继续使用旧配置并输出明确错误日志。
- `AC-2-4` 多上游节点转发请求时，轮询分配比例误差小于 10%。
- `AC-2-5` 某上游节点满足摘除条件时：
  - 主动摘除：连续 3 次主动探测失败。
  - 被动摘除：5 秒滑动窗口失败率不低于 80% 且失败次数不少于 5 次。
  - 当摘除后健康实例数不低于 `minHealthyInstances` 时，必须自动摘除且流量不再转发到该节点。
  - 当摘除后健康实例数低于 `minHealthyInstances` 时，必须进入降级态并输出告警，不得执行摘除。
- `AC-2-6` 故障节点连续 2 次主动探测成功后，必须自动重新纳入负载。
- `AC-2-7` 非“配置唯一真源（Single Source of Truth）”发起的运行时写入请求必须被拒绝并记录审计日志。
- `AC-2-8` 协议路由扩展位验收：配置模型必须包含协议类型与 L4 维度占位字段（端口、SNI、目标组），且在未启用 L4 的情况下不影响 HTTP 路由行为。
- `AC-2-9` 路由优先级验收：存在重叠路由规则时，请求命中结果必须符合 `FR-2-12` 定义且可重复复现。

## 6. 测试要求
- 单元测试：
  - 路由优先级
  - 路径重写
  - 轮询负载均衡
  - 配置校验
  - 健康检查状态机（主动/被动/恢复）
  - `minHealthyInstances` 降级保护逻辑
- 集成测试：
  - 热更新前后请求正确性
  - 更新失败回滚正确性
  - 健康检查摘除/恢复与降级态行为
  - 非真源运行时写入拒绝与审计日志
  - 重叠路由命中优先级一致性

## 7. 设计输入清单
- 路由 DSL/配置模型定义
- 配置版本管理与原子切换设计
- 路由匹配算法与数据结构
- 负载均衡策略接口定义
- 服务发现抽象接口占位（本阶段不实现具体注册中心适配）
- 健康检查状态机与 `minHealthyInstances` 降级策略
- 路由优先级判定规则与冲突消解策略

## 8. 风险与约束
- `RISK-2-1` 热更新若非原子替换，容易产生并发读写问题。
- `RISK-2-2` 路由优先级规则不明确会导致线上行为不确定。
- `RISK-2-3` 健康检查摘除若缺少最小健康实例保护，可能导致全量摘除与路由雪崩。
