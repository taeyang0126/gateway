# 阶段 3 需求：长连接网关能力

## 1. 阶段目标
- 在 HTTP 代理能力稳定后，补齐长连接网关能力。
- 按学习曲线拆分为 3A/3B：先支持 WebSocket，再支持 TCP Tunnel（四层透传）。

## 2. 范围
### 2.1 In Scope
- WebSocket 握手与消息双向转发
- WebSocket 心跳与空闲连接回收
- TCP Tunnel 建链与字节流透传
- L4 路由模型（监听端口、SNI、目标组）
- 长连接会话管理（连接、断开、异常）

### 2.2 Out of Scope
- 自定义二进制协议解析
- IM 业务协议层语义处理
- 多租户连接配额

## 3. 功能需求
- `FR-3-1` 支持 HTTP Upgrade 到 WebSocket，并完成上游代理握手。
- `FR-3-2` 支持 Text/Binary/Ping/Pong/Close 帧的双向透传。
- `FR-3-3` 支持配置空闲超时，超时后主动关闭连接并记录原因。
- `FR-3-4` 支持 L4 路由规则：
  - 按监听端口匹配目标组。
  - TLS 场景支持按 SNI 匹配目标组。
  - 目标组支持轮询负载均衡。
- `FR-3-5` 支持 TCP Tunnel，将客户端字节流无状态转发到目标上游。
- `FR-3-6` 支持连接生命周期事件日志：建立、断开、异常、时长、收发字节。
- `FR-3-7` 支持连接级别统计指标：当前连接数、建连速率、断连原因分布。
- `FR-3-8` 阶段 3A 仅交付 WebSocket；阶段 3B 交付 TCP Tunnel 和 L4 路由。

## 4. 非功能需求
- `NFR-3-1` 单机 WebSocket 稳定连接目标不低于 20,000（2C4G 开发机参考值）。
- `NFR-3-2` 长连接稳态运行 12 小时无明显内存泄漏与 FD 泄漏。
- `NFR-3-3` 连接断开后资源（Channel、ByteBuf、连接记录）必须及时释放。
- `NFR-3-4` 长连接压测最小画像（默认口径）：
  - WebSocket 消息大小 1KB，心跳周期 30 秒。
  - 活跃连接比例 20%（其余连接仅心跳保活）。
  - TCP Tunnel 流量模型采用 1KB 报文、每连接 5 qps。

## 5. 验收标准
- `AC-3-1`（3A）WebSocket 客户端可经网关与上游完成双向消息通信。
- `AC-3-2`（3A）心跳超时连接可被及时剔除，超时阈值误差不超过 10%。
- `AC-3-3`（3B）TCP Tunnel 可稳定传输二进制流，数据完整性校验通过。
- `AC-3-4`（3B）L4 路由可按端口和 SNI 正确命中目标组。
- `AC-3-5`（3A/3B）压测 12 小时后满足：
  - 进程 RSS 相比第 2 小时基线增幅不超过 15%。
  - FD 数量在稳态窗口内波动不超过 ±10%。
  - 不得出现持续 30 分钟以上的内存或 FD 单调增长。
- `AC-3-6`（3A/3B）连接规模与稳定性验收必须基于 `NFR-3-4` 的最小画像执行并在报告中记录参数。

## 6. 测试要求
- 单元测试：
  - 会话状态机
  - 超时关闭逻辑
  - 异常处理与清理
- 集成测试：
  - WebSocket 端到端代理
  - TCP 透传正确性
  - 长稳连接测试

## 7. 设计输入清单
- 长连接会话模型（Session）
- WebSocket 与 TCP Pipeline 设计
- Idle/Heartbeat 策略设计
- 连接指标采集点定义

## 8. 风险与约束
- `RISK-3-1` 长连接场景若日志过量会显著影响吞吐与延迟。
- `RISK-3-2` 若缺少资源回收审计，容易出现慢性泄漏问题。
- `RISK-3-3` 若 3A/3B 不分阶段验收，排障复杂度和学习成本会显著升高。
