# 阶段 3 需求：长连接网关能力

## 0. 版本状态
- 状态：`FROZEN`
- 冻结日期：2026-03-15
- 冻结说明：阶段3A/3B/3C需求已完成评审与冻结，后续改动需走需求变更流程并记录到 `CHANGELOG-REQUIREMENTS.md`。

## 1. 阶段目标
- 在 HTTP 代理能力稳定后，补齐长连接网关能力。
- 按学习曲线拆分为 3A/3B/3C：先支持 WebSocket，再支持 TCP Tunnel（四层透传），最后交付推送网关能力。

## 2. 范围
### 2.1 In Scope
- WebSocket 握手与消息双向转发
- WebSocket 心跳与空闲连接回收
- TCP Tunnel 建链与字节流透传
- L4 路由模型（监听端口、SNI、目标组）
- 长连接会话管理（连接、断开、异常）
- 推送入口统一接入（SDK、RPC、MQ）
- 在线定向推送与广播推送
- 离线消息存储、重连拉取、ACK 与重投

### 2.2 Out of Scope
- 自定义二进制协议解析
- IM 业务协议层语义处理
- 多租户连接配额
- 跨机房多活一致性

## 3. 功能需求
- `FR-3-1` 支持 HTTP Upgrade 到 WebSocket，并完成上游代理握手。
- `FR-3-2` 支持 Text/Binary/Ping/Pong/Close 帧的双向透传。
- `FR-3-3` 支持配置空闲超时，超时后主动关闭连接并记录原因。
- `FR-3-4` 支持 L4 路由规则：
  - 按监听端口匹配目标组。
  - TLS 场景支持按 SNI 匹配目标组。
  - 目标组支持轮询负载均衡。
- `FR-3-5` 支持 TCP Tunnel，将客户端字节流无状态转发到目标上游。
- `FR-3-6` 支持连接生命周期事件日志：建立、断开、异常、时长、收发字节。
- `FR-3-7` 支持连接级别统计指标：当前连接数、建连速率、断连原因分布。
- `FR-3-8` 阶段 3A 仅交付 WebSocket；阶段 3B 交付 TCP Tunnel 和 L4 路由；阶段 3C 交付推送网关能力。
- `FR-3-9`（3C）提供 3 种推送入口：SDK、RPC、MQ。三种入口必须映射到统一消息模型并共用同一投递内核。
- `FR-3-10`（3C）支持在线推送目标路由：`userId`、`deviceId`、`connectionId` 三种定向方式；支持受控广播。
- `FR-3-11`（3C）支持离线消息持久化，至少包含 `messageId`、目标标识、消息体、创建时间、过期时间（TTL）、投递状态。
- `FR-3-12`（3C）支持客户端重连后拉取未 ACK 消息，拉取接口必须支持游标（cursor）与批量窗口。
- `FR-3-13`（3C）支持 ACK 与重投：超时未 ACK 可按策略重投，超过最大重投次数后进入死信队列并记录原因。
- `FR-3-14`（3C）支持幂等去重：以 `deliveryKey = messageId + routeType + routeValue` 作为幂等键；广播场景必须先 fanout 到具体目标后再去重。
- `FR-3-15`（3C）支持推送链路指标：入口吞吐、在线投递成功率、离线积压量、拉取成功率、ACK 延迟分布、重投次数、死信数量。
- `FR-3-16`（3C）支持背压与限流策略，保障推送入口和离线拉取在高负载下不阻塞事件循环。
- `FR-3-17`（3C）投递语义定义：
  - 在线投递链路默认 `at-most-once`。
  - 离线拉取链路采用 `at-least-once`（TTL 窗口内可重复拉取）。
  - 阶段 3C 不承诺端到端 `exactly-once`，业务侧通过幂等键实现“效果一次”。
- `FR-3-18`（3C）统一消息契约必须包含：`schemaVersion`、`messageId`、`traceId`、`sourceType`（SDK/RPC/MQ）、目标路由信息、`ttl`、创建时间。
- `FR-3-19`（3C）三入口必须收敛到统一错误码体系，明确可重试错误与不可重试错误，返回语义一致。
- `FR-3-20`（3C）ACK 与离线拉取必须定义统一状态机：`NEW -> DELIVERED -> ACKED`，并允许 `NEW/DELIVERED/RETRY -> RETRY/DLQ/EXPIRED`；状态迁移必须单调且原子。任一投递前必须先检查 TTL，已过期消息直接进入 `EXPIRED` 终态。
- `FR-3-21`（3C）重试策略必须明确默认参数：`ackTimeout=30s`、`maxRetries=5`、`backoff=指数退避(初始1s, 上限60s, 抖动±20%)`、`retryConcurrency=500`（可配置范围 `100~5000`）；并按场景区分：
  - 在线投递链路不做重复投递重试（保持 `at-most-once` 语义）。
  - 离线拉取链路与内部瞬时故障恢复链路允许重试（遵循统一重试策略）。
- `FR-3-22`（3C）TTL 与重试优先级必须明确：消息 TTL 到期后优先进入 `EXPIRED`，不得再进入重试或投递链路。
- `FR-3-23`（3C）离线拉取必须定义排序与游标语义（按 `createdAt + messageId` 稳定排序），并支持并发重连场景下的一致性拉取。
- `FR-3-24`（3C）推送链路可观测性必须支持 `messageId/traceId` 全链路关联查询，覆盖入口、投递、ACK、重试、死信各阶段。

## 4. 非功能需求
- `NFR-3-1` 单机 WebSocket 稳定连接目标不低于 20,000（2C4G 开发机参考值）。
- `NFR-3-2` 长连接稳态运行 12 小时无明显内存泄漏与 FD 泄漏。
- `NFR-3-3` 连接断开后资源（Channel、ByteBuf、连接记录）必须及时释放。
- `NFR-3-4` 长连接压测最小画像（默认口径）：
  - WebSocket 消息大小 1KB，心跳周期 30 秒。
  - 活跃连接比例 20%（其余连接仅心跳保活）。
  - TCP Tunnel 流量模型采用 1KB 报文、每连接 5 qps。
- `NFR-3-5`（3C）在线推送端到端时延（入口接收成功到客户端收到）P99 不高于 500ms（压测口径：1KB 消息体）。
- `NFR-3-6`（3C）离线拉取接口在单次拉取 100 条、每条 1KB 的口径下，响应时延 P99 不高于 800ms。
- `NFR-3-7`（3C）离线消息默认保留期为 72 小时；超过 TTL 必须自动过期并可审计。
- `NFR-3-8`（3C）离线积压恢复能力：网关从不可用恢复后，30 分钟内应完成至少 95% 的积压投递恢复（以未过期消息为口径）。
- `NFR-3-9`（3C）推送与拉取链路在稳态 12 小时运行期间，不得出现持续 30 分钟以上的离线积压单调增长。
- `NFR-3-10`（3C）推送入口、重投任务、离线拉取均必须采用无阻塞实现，禁止在 Netty 事件循环中执行阻塞 IO。
- `NFR-3-11`（3C）正确性指标（统计窗口 1 小时）：
  - TTL 内消息丢失率不高于 0.01%。
  - 重复投递率不高于 0.1%。
  - 误投率（投递到非目标）必须为 0。
- `NFR-3-12`（3C）幂等去重状态保留时长必须覆盖 `max(ttl, 最大重试窗口)`，避免重连或重试导致重复生效。
- `NFR-3-13`（3C）资源回收量化要求：
  - 连接断开后 60 秒内 `Channel` 与连接索引残留必须为 0。
  - FD 数量在断连后 120 秒内回落到稳态窗口。
- `NFR-3-14`（3A/3B/3C）在 20,000 WebSocket 连接口径下：
  - CPU 使用率不高于 70%。
  - Heap 使用率不高于 75%。
  - GC Pause P99 不高于 100ms。
- `NFR-3-15`（3C）背压阈值要求：
  - 队列利用率超过 80% 且持续 10 秒必须触发限流。
  - 队列利用率超过 95% 必须触发受控拒绝。
  - 队列利用率低于 60% 且持续 30 秒方可退出背压。
- `NFR-3-16`（3C）背压触发期间，事件循环延迟 P99 不高于 50ms，不得出现全局阻塞。
- `NFR-3-17`（3A/3B/3C）压测报告必须记录统一口径：连接数、活跃比例、消息大小、建连速率、断连速率、TLS 开关、上下游 RTT/丢包、测试时长。
- `NFR-3-18`（3C）背压指标定义与阈值：
  - `queueUsage = queueSize / queueCapacity`，用于限流/拒绝触发与恢复判定（对应 `NFR-3-15`）。
  - `rejectRate`（单位时间内被限流/拒绝请求占比）在稳态目标负载下不高于 1%。
  - `offlineBacklogGrowth`（离线积压增长斜率）不得连续 30 分钟为正增长。
  - `ackTimeoutRate` 与 `retryInflight` 必须可观测；当 `ackTimeoutRate > 2%` 且持续 3 分钟时触发入口收紧，当 `ackTimeoutRate < 0.5%` 且持续 10 分钟时恢复。
  - `memoryWatermark`（Heap/DirectMemory 水位）阈值：`>85%` 触发降速，`>92%` 触发受控拒绝，`<75%` 且持续 5 分钟方可恢复。

## 5. 验收标准
- `AC-3-1`（3A）WebSocket 客户端可经网关与上游完成双向消息通信。
- `AC-3-2`（3A）心跳超时连接可被及时剔除，超时阈值误差不超过 10%。
- `AC-3-3`（3B）TCP Tunnel 可稳定传输二进制流，数据完整性校验通过。
- `AC-3-4`（3B）L4 路由可按端口和 SNI 正确命中目标组。
- `AC-3-5`（3A/3B）压测 12 小时后满足：
  - 进程 RSS 相比第 2 小时基线增幅不超过 15%。
  - FD 数量在稳态窗口内波动不超过 ±10%。
  - 不得出现持续 30 分钟以上的内存或 FD 单调增长。
- `AC-3-6`（3A/3B）连接规模与稳定性验收必须基于 `NFR-3-4` 的最小画像执行并在报告中记录参数。
- `AC-3-7`（3C）SDK、RPC、MQ 三种入口均可将消息写入统一投递链路，且消息模型字段校验一致。
- `AC-3-8`（3C）客户端离线后重连可拉取到 TTL 内未 ACK 消息；在 10,000 用户离线重连演练中，拉取完整率不低于 99.99%，且必须满足 `NFR-3-11` 正确性指标。
- `AC-3-9`（3C）ACK/重投/死信流程可验证：未 ACK 消息可按策略重投，超过最大重试次数后进入死信并可追踪原因。
- `AC-3-10`（3C）在线推送与离线拉取性能分别满足 `NFR-3-5`、`NFR-3-6`、`NFR-3-8`，并在验收报告中记录压测参数与结果。
- `AC-3-11`（3C）3A/3B/3C 联合长稳 12 小时后，除满足 `AC-3-5` 外，还需满足 `NFR-3-9` 的离线积压稳定性要求。
- `AC-3-12`（3C）同一消息经 SDK/RPC/MQ 重复提交并叠加重试场景下，每个 `deliveryKey` 仅允许一次业务生效。
- `AC-3-13`（3C）并发重连 + 重复拉取 + 乱序 ACK 场景下，不得出现“ACK 后再次投递”与状态回退。
- `AC-3-14`（3C）TTL 边界验收：接近过期消息在 TTL 到期后必须进入 `EXPIRED`，不得再次重试或投递。
- `AC-3-15`（3C）背压验收：必须验证触发阈值、受控拒绝、恢复阈值三段行为，且满足 `NFR-3-15`、`NFR-3-16`。
- `AC-3-16`（3A/3B/3C）在 20,000 WebSocket 连接规模验收中，必须满足 `NFR-3-14` 资源阈值要求。
- `AC-3-17`（3C）故障注入验收：上游抖动、MQ 降速、连接风暴场景下，正确性与稳定性必须满足 `NFR-3-11`、`NFR-3-8`、`NFR-3-9`、`NFR-3-16`，且报告记录口径必须满足 `NFR-3-17`。
- `AC-3-18`（3C）背压指标验收：`queueUsage`、`rejectRate`、`offlineBacklogGrowth`、`ackTimeoutRate`、`retryInflight`、`memoryWatermark` 均可采集并在报告中给出阈值命中证据。

  - 推送入口（SDK/RPC/MQ）一致性测试

## 8. 风险与约束
- `RISK-3-1` 长连接场景若日志过量会显著影响吞吐与延迟。
- `RISK-3-2` 若缺少资源回收审计，容易出现慢性泄漏问题。
- `RISK-3-3` 若 3A/3B/3C 不分阶段验收，排障复杂度和学习成本会显著升高。
- `RISK-3-4` 若幂等键设计不当，可能出现重复投递导致业务重复生效。
- `RISK-3-5` 若离线积压缺少过期与背压控制，可能引发存储膨胀和恢复风暴。
- `RISK-3-6` 若 ACK 状态机与 cursor 语义不一致，可能导致漏投、重投风暴或状态回退。
- `RISK-3-7` 若重试策略缺少抖动与并发上限，故障恢复期可能放大雪崩效应。
