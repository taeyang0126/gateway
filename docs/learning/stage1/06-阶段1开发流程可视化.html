阶段1开发流程可视化看板

从需求到实现的全链路视图：流程步骤、放行条件、需求与代码/测试/证据映射。

名词解释（FR / NFR / AC）

FR（Functional Requirement）

功能需求：系统“必须做什么”。例如：请求转发、健康检查、错误映射。

NFR（Non-Functional Requirement）

非功能需求：系统“做到什么程度”。例如：性能、稳定性、资源使用上限。

AC（Acceptance Criteria）

验收标准：如何判定需求已完成。通常对应明确的测试结果或压测证据。

流程步骤（强制执行）

Step 1

需求定义

产出 FR/NFR/AC，明确范围与验收标准。

Step 2

设计产出

完成 01 概要 + 02 任务 + 03 详细设计。

Step 3

实现与测试

按任务依赖顺序编码，补齐单测/集成测试。

Step 4

回填矩阵

填写代码实现、测试用例、证据、状态。

Step 5

更新 Gate

阶段结论写入 GateStatus，并补验收说明。

Step 6

双校验放行

通过质量门禁与 strict 校验后再提交推送。

放行条件（决策树）

1. GateStatus = PASS ? 否 -> 不允许提交 | 是 -> 继续
2. 矩阵状态全 PASS 且 代码/测试/证据完整 ? 否 -> 不允许提交 | 是 -> 继续
3. `run-quality.sh` 与 `verify-stage.sh --strict` 均通过 ? 否 -> 修复后重跑 | 是 -> 可提交
代码质量门禁
./scripts/ci/run-quality.sh
流程闭环门禁
./scripts/requirements/verify-stage.sh 1 --strict
