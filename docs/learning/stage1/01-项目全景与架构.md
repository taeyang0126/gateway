# 阶段 1 项目全景与架构

## 1. 模块边界
- 根工程：统一依赖管理、质量插件、CI 配置。
- `gateway-server/`：阶段 1 业务模块，提供 HTTP 反向代理能力。
- `scripts/perf/stage1/`：压测脚本与 Gatling Simulation。
- `reports/stage1/`：压测与稳定性输出证据。

## 2. 请求处理主链路
```text
Client Request
  -> Netty Pipeline
  -> DefaultHttpServerHandler
  -> RouteService(匹配路由)
  -> HeaderPolicyService(头处理)
  -> Upstream Forward
  -> ErrorResponseMapper(异常映射)
  -> Client Response
```

## 3. 核心设计点
- 路由策略：支持优先级 + 匹配类型 + 最长前缀原则。
- Host 策略：
  - `REWRITE`：`Host` 改写为 upstream host:port
  - `PRESERVE`：保留原始 `Host`
- Trace 策略：统一使用并透传 `X-Trace-Id`。
- 连接模型：按路由复用连接，控制在途请求，避免每请求建连。

## 4. 你需要重点阅读的类
- 启动生命周期：`GatewayBootstrap`
- Pipeline 组装：`ServerPipelineFactory`
- 主处理器：`DefaultHttpServerHandler`
- 路由：`StaticRouteService`
- Header 策略：`DefaultHeaderPolicyService`
- 错误映射：`DefaultErrorResponseMapper`

## 5. 关键原则
- 先保证可验证性，再追求复杂能力扩展。
- 设计必须能映射到测试和证据，不做“不可验证”的实现。
