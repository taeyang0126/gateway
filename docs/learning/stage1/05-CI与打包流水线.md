# 阶段 1 CI 与打包流水线

## 1. 现有 CI 工作流
- `quality-gate.yml`：执行质量门禁（格式、静态检查、测试、覆盖率）。
- `quality-config.yml`：校验质量配置与 Maven 配置可解析性。
- `package-build.yml`：执行打包构建、fat-jar 启动冒烟并上传产物。

> 说明：双看板同步（06 + 07）属于流程强制项，规则定义在 `AGENTS.md`，不通过单独 CI 工作流实现。

## 2. 为什么要加打包工作流
- 质量通过不等于可交付。
- 单独加打包工作流可以保证每次变更都能稳定产出构建物，提前暴露打包断裂问题。

## 3. 打包工作流做了什么
1. 使用 JDK 24 构建环境。
2. 执行 `./mvnw -B -ntp -DskipTests package`。
3. 用 `java -Xms256m -Xmx256m -jar ...` 启动 fat-jar 做冒烟。
4. 校验 `/health` 与 `/metrics/prometheus` 均返回 200。
5. 上传 `gateway-server/target/*.jar` 作为 CI Artifact。

## 4. 学习者要会的两件事
- 区分“质量门禁失败”和“打包失败”的问题边界。
- 能从 CI Artifact 下载并验证 JAR 是否可运行。
