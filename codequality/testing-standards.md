# Testing Standards

## 1. 测试分层
- **单元测试**：无网络、无数据库、无外部进程，必须可并行执行。
- **集成测试**：允许 Testcontainers，覆盖协议边界和组件协作。

## 2. 框架约束
- JUnit 5 + AssertJ + Mockito（`STRICT_STUBS`）
- 集成测试优先 Testcontainers，不允许依赖共享外部环境

## 3. 命名规范
- 单元测试类：`*Tests.java`
- 集成测试类：`*IT.java`（或 `*ST.java`）
- 测试方法：`should_<行为>_when_<条件>`

## 4. 编写规则
- 使用 AAA（Arrange-Act-Assert）结构。
- 一个测试只验证一个行为，不写“全能大测试”。
- 禁止 `Thread.sleep`；改用可控时钟、轮询等待或事件同步。
- 禁止随机数据无种子；需要可复现。
- Bug 修复必须附带回归测试。

## 5. 质量门槛
- 当前质量门禁阈值：行覆盖率 >= 80%，分支覆盖率 >= 55%（与 `pom.xml` 一致）。
- 目标阈值：行覆盖率 >= 85%，分支覆盖率 >= 75%（阶段性收敛）。
- 核心模块（协议编解码、路由、会话）行覆盖率建议 >= 90%。
- 新增功能必须同时提交正向用例和关键异常路径用例。

## 6. 执行建议
- 本地开发：优先跑模块级测试。
- 提交前：至少执行一次全量 `mvn verify`。
